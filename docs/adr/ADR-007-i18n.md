# ADR-007: 国际化（i18n）方案

## 状态
✅ 已采纳

## 上下文
修仙世界模拟器需要支持多语言，主要目标语言：
- **简体中文**（zh-CN）: 主要语言
- **英文**（en-US）: 国际化支持
- **繁体中文**（zh-TW）: 补充支持

### 需求
1. **前后端分离**: 前端 UI 文本、后端事件描述都需要翻译
2. **动态切换**: 用户可以在运行时切换语言
3. **资源分离**: 游戏数据（功法、宗门）也需要多语言
4. **LLM 适配**: LLM 生成的内容需要匹配当前语言

### 翻译内容
- **前端**: UI 文本（按钮、标签、提示）
- **后端**: 事件描述、系统消息
- **资源**: 功法名称、境界名称、物品名称
- **LLM**: 提示词、生成的对话和描述

## 决策
采用 **前后端分离的 i18n 方案 + 资源文件多语言分离**。

## 架构设计

### 1. 前端国际化（Vue I18n）

#### 安装和配置

```typescript
// web/src/locales/index.ts
import { createI18n } from 'vue-i18n'

  legacy: false,  // 使用 Composition API 模式

    'en-US': enUS,

export default i18n
```

### 2. 后端国际化（自定义实现）

#### 配置语言


#### 翻译管理器

```python
# src/utils/i18n.py
import json
from pathlib import Path
from typing import Dict

class I18n:
    """后端国际化管理器"""

    def __init__(self, language: str = "zh-CN"):
        self.language = language
        self.translations: Dict[str, Dict] = {}
        self._load_translations()

    def _load_translations(self):
        """加载翻译文件"""
        i18n_dir = Path(__file__).parent.parent / "locales"

        for lang in ["zh-CN", "en-US", "zh-TW"]:
            file_path = i18n_dir / f"{lang}.json"
            if file_path.exists():
                with open(file_path, 'r', encoding='utf-8') as f:
                    self.translations[lang] = json.load(f)

    def t(self, key: str, **kwargs) -> str:
        """翻译文本"""
        # 分割键名（如 "event.breakthrough"）
        keys = key.split('.')
        value = self.translations.get(self.language, {})

        # 逐层查找
        for k in keys:
            if isinstance(value, dict):
                value = value.get(k)
            else:
                break

        # 如果未找到，回退到中文
        if not value:
            value = self.translations.get("zh-CN", {})
            for k in keys:
                if isinstance(value, dict):
                    value = value.get(k)
                else:
                    break

        # 未找到则返回键名
        if not value:
            return key

        # 格式化参数
        if kwargs:
            return value.format(**kwargs)

        return value

    def set_language(self, language: str):
        """切换语言"""
        if language in self.translations:
            self.language = language

# 全局单例
i18n = I18n(language=CONFIG.system.language)
```

```python
def generate_breakthrough_event(avatar: Avatar) -> Event:
```

### 4. LLM 多语言适配

#### 提示词模板

```python
# src/utils/llm/prompts.py
def build_decision_prompt(avatar: Avatar) -> str:
    """构造决策提示词（根据语言）"""

    if i18n.language == "zh-CN":
        return f"""
你是修仙世界中的角色：{avatar.name}

# 基本信息
- 境界：{avatar.realm.display_name}
- 年龄：{avatar.age} 岁
- 宗门：{avatar.sect.name if avatar.sect else "散修"}

请根据以上信息，决定下一步动作。
"""
    elif i18n.language == "en-US":
        return f"""
You are a character in the cultivation world: {avatar.name}

# Basic Info
- Realm: {avatar.realm.display_name}
- Age: {avatar.age} years old
- Sect: {avatar.sect.name if avatar.sect else "Rogue Cultivator"}

Based on the above information, decide your next action.
"""
    else:
        # 回退到中文
        return build_decision_prompt_zh_cn(avatar)
```

#### LLM 响应解析

LLM 返回的 JSON 键名保持英文（统一）：

```json

  "reasoning": "I need to improve my cultivation",
  "thought": "I'm still too weak"
```


### 5. 动态语言切换

#### 前端切换

```typescript
// 语言切换（前端）
import { useI18n } from 'vue-i18n'
import { gameAPI } from '@/api/game'

const { locale } = useI18n()

async function switchLanguage(lang: string) {
  // 1. 切换前端语言
  locale.value = lang

  // 2. 通知后端切换语言
  await gameAPI.setLanguage(lang)

  // 3. 重新加载游戏状态（刷新事件描述）
  await gameStore.fetchState()
}
```

#### 后端切换

```python
# API 端点
@app.post("/api/config/language")
async def set_language(language: str):
    """设置语言"""
    # 更新配置
    CONFIG.system.language = language

    # 重新加载翻译
    i18n.set_language(language)

    # 保存配置到文件
    save_config()

    return {"status": "ok", "language": language}
```

## 权衡

### 优点
- ✅ 前后端分离（各自管理翻译）
- ✅ 动态切换（无需重启）
- ✅ 资源分离（游戏数据多语言分离）
- ✅ LLM 适配（提示词根据语言变化）
- ✅ 回退机制（未翻译时显示中文）

### 缺点
- ❌ 翻译文件需要同步维护（容易遗漏）
- ❌ 资源文件重复（每种语言一份）

## 替代方案

### 方案 1: 统一翻译文件（前后端共用）
- **优点**: 翻译文件统一，易于维护
- **缺点**:
  - 前后端耦合（前端需要加载后端翻译）
  - 包体积增大（前端包含后端翻译）

**为什么不选**: 前后端耦合，违背分离原则。

### 方案 2: 数据库存储翻译
- **优点**: 动态管理（可以热更新翻译）
- **缺点**:
  - 性能差（每次翻译都查数据库）
  - 复杂度高（需要管理翻译表）

**为什么不选**: 过于复杂，性能差。

### 方案 3: 机器翻译（如 Google Translate API）
- **优点**: 自动翻译，无需人工维护
- **缺点**:
  - 翻译质量差（修仙术语难以准确翻译）
  - 依赖网络（离线无法使用）
  - 成本高（API 调用费用）

**为什么不选**: 翻译质量不可控。

## 后果

### 正面
- 支持多语言用户（国际化）
- 动态切换语言（用户体验好）
- 资源文件分离（游戏数据也能翻译）
- LLM 生成内容匹配用户语言

### 负面
- 翻译文件需要维护（容易遗漏新增文本）
- 资源文件重复（每种语言一份 CSV）

## 经验教训
- Vue I18n 的 Composition API 模式比 Options API 更好用
- 后端翻译使用字符串格式化（`.format()`）比模板引擎简单
- 资源文件分离避免了 CSV 中混合多语言列
- LLM 提示词需要根据语言调整（文化差异）

## 未来优化方向
- [ ] 引入翻译管理平台（如 Crowdin）协作翻译
- [ ] 支持更多语言（日语、韩语）
- [ ] 自动检测缺失翻译（CI/CD 集成）
- [ ] 支持方言变体（如台湾国语、香港粤语）
